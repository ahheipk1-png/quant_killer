# contracts/ — the single source of truth

Everything that must be **identical across all four languages** (Python, C++, C#, Rust) lives here.

| File | Purpose |
|------|---------|
| `schema/request.schema.json` | JSON shape of a pricing request (used by every CLI and the FFI JSON entry point) |
| `schema/response.schema.json` | JSON shape of a pricing response |
| `rng-spec.md` | The frozen numeric spec: PCG32 RNG, uniform mapping, inverse-normal CDF, `norm_cdf` |
| `vectors/*.json` | Golden test vectors — inputs + expected outputs for every model |

## Rules

1. **Never edit `vectors/*.json` by hand.** They are generated by `python/gen_vectors.py`
   from the Python reference implementation, which is itself cross-checked against an
   independent `math.erf`-based oracle in `python/tests/`.
2. Every language's test suite loads these same vector files and must pass them. Currently:
   `python/tests/`, `csharp/tests/QuantKiller.Tests/VectorTests.cs`, `rust/quantkiller/tests/vectors.rs`,
   `cpp/tests/vector_tests.cpp` — all four pass the same 41 cases across 11 vector files as of
   the American-methods merge.
3. `scripts/test_crosslang.py` goes one step further: it runs the *live CLI binary* of every
   language that's currently built (not the in-process library) on every vector case, and diffs
   every pair of engines' JSON output within tolerance. This is the strongest proof in the repo
   — it exercises real process invocation and JSON encode/decode, catching bugs the per-language
   vector tests structurally can't (e.g. a CLI argument-parsing or serialization bug that a
   direct function call would never hit). Run it after building at least two languages'
   CLIs.
3. Expected values are compared as
   `|actual − expected| ≤ abs_tol + rel_tol · |expected|`,
   with tolerances declared *inside each vector file*. Typical values:
   closed-form `1e-10` rel · trees/finite-difference `1e-11` rel · Monte Carlo & quadrature `1e-9` rel ·
   abs floor `1e-12`.
   (Cross-language results differ in the last bits because `exp`/`log`/`pow` are not required
   by IEEE-754 to be correctly rounded and each runtime ships its own libm — see `rng-spec.md`.)

## Request / response protocol (CLI + FFI)

Request:

```json
{
  "model": "black_scholes",
  "params": {
    "spot": 42.0, "strike": 40.0, "rate": 0.10, "div_yield": 0.0,
    "vol": 0.20, "time": 0.5, "option_type": "call"
  }
}
```

Response:

```json
{
  "ok": true,
  "model": "black_scholes",
  "engine": "python/0.1.0",
  "results": { "price": 4.759422392871532, "delta": 0.7791312909683213, "...": 0 }
}
```

Error response: `{ "ok": false, "error": "message" }`.

Conventions (all languages): continuously compounded `rate`/`div_yield`; `time` in year
fractions; `vol` annualized; `theta` per year; `vega`/`rho` per unit of vol/rate.
