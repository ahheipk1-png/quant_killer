# Whole-project review - 2026-08-03

> Review status: recommendations and implementation findings were rechecked during the documentation synchronization on 2026-08-04.

## Executive assessment

QuantKiller is already a substantial browser-based quantitative research lab. Its strongest qualities are the local-only execution model, deterministic multi-language comparisons, broad payoff coverage, explicit numerical reductions, and an unusually useful executable HTML specification. The current code and documentation generally distinguish research implementations from production claims.

The next major improvement should not be another long list of payoffs. It should be a release-engineering and model-governance layer around what is already here. In its present form the project is a strong research and demonstration library, but it is not yet a production pricing service or independently validated model library.

No priority item from this review should be read as already implemented merely
because it appears below. Delivery status belongs in `docs/roadmap.md`; the
review records the rationale and recommended order.

## Scope and evidence reviewed

- Loaded all seven browser pages through the local HTTP server: vanilla/American, exotics, portfolio, path distribution, volatility calibration, tests, and four-language conformance.
- Exercised the CVI fit in the visible Volatility Surface Lab.
- Ran all eight Node suites: smoke, exotic, advanced, PDE, path distribution, pricing regression, portfolio, and volatility.
- Confirmed the browser report passes 182/182 checks in 26 groups.

- Checked local HTML references and IDs; no missing local `href`/`src` targets or duplicate IDs were found.
- Inspected the worker structure, language dispatch, packed polyglot contract, local server, bundled runtime size, documentation, and current repository state.

The review also found and corrected a CVI integration gap. The denser browser diagnostic sampled maturities between quoted expiries and initially found butterfly violations that the smaller test grid missed. CVI now constrains intermediate maturities, uses matching linear-total-variance interpolation, exposes the constraint interpolation in its parameters, and passes the visible 328-point butterfly/calendar audit.

## What is already strong

1. **Client-side privacy by construction.** The supplied server only serves static assets on `127.0.0.1`; deal data is priced in browser workers and is not posted to a pricing endpoint.
2. **Executable numerical documentation.** Payoff examples, identities, reductions, independent-method comparisons, and calibration tests are visible in HTML rather than hidden in an opaque test log.
3. **Deterministic cross-language contract.** Seeded streams and common public serialization make C++, Rust, Python, and C# behavior directly comparable.
4. **Good separation of claims.** The documentation states where JavaScript has formula/PDE/QMC breadth and where compiled advanced engines currently expose only seeded Monte Carlo.
5. **Broad numerical coverage.** The library includes formulas, trees, PDE/ADI, MC/QMC, early exercise, baskets, path-dependent products, realized-volatility products, surface fitting, Dupire, and an SLV demonstrator.
6. **Responsive pricing architecture.** Expensive deal and path jobs normally run in workers, request IDs protect against stale responses, and the language runtimes are lazy-loaded outside the dedicated conformance page.

## Important interpretation of the surface methods

- The corrected default CVI sample passes the denser 328-point butterfly/calendar audit. That remains a sampled diagnostic, not a proof over the continuous domain.
- PCHIP variance is an exact nodal interpolator, not a globally arbitrage-constrained surface. The current dense sample audit finds two butterfly flags, which the UI correctly reports.
- The convex-call method enforces direct call-price bounds, monotonicity, and convex nodal slopes. Its piecewise interpolation has derivative kinks, so a smooth total-variance density diagnostic can report many flags even while the direct price-space checks pass. These two diagnostics should remain visibly distinguished.

## Prioritized recommendations

### P0 - establish a reproducible release baseline

1. **Put this subproject under an explicit version-control baseline.** In the current parent worktree the entire `wasm-mc-demo` directory is reported as untracked. Create a reviewed initial commit before more numerical expansion so later changes, generated artifacts, and model results can be audited.
2. **Add a standard test entry point and CI.** There is no `package.json` or CI configuration. Add scripts such as `test:node`, `test:browser`, and `test:all`; run all eight Node suites plus a headless browser pass on every change.
3. **Add licensing and third-party notices.** No project license was found. Bundled Pyodide, .NET, Emscripten/Rust artifacts, source papers, and any future market-data adapters should have explicit attribution and redistribution records.
4. **Treat a calibrated surface as a versioned model artifact.** Define a JSON schema containing quote snapshot, curves, conventions, fitter/version, parameters, constraints, diagnostics, tolerances, and timestamps. This is the missing boundary between the calibration lab and the pricing engines.

### P1 - increase numerical confidence, not just method count

5. **Build a convergence harness.** For every numerical method, report price sequences under grid/path/time-step refinement and an observed convergence indicator. Add Greek convergence, not only price convergence.
6. **Test calibration on imperfect data.** Extend clean synthetic round trips with bid/ask spreads, sparse and irregular strikes, noisy quotes, crossed quotes, low-Vega wings, negative rates, discrete dividends, and deliberately inconsistent calendars. Report what was rejected, repaired, or left flagged.
7. **Connect calibrated volatility to pricing.** Today `volatility-models.js` is separate from the packed four-language pricing ABI. Load the versioned surface artifact into vanilla, exotic, portfolio, and path engines, then add price/Greek regressions using the identical calibrated input.
8. **Finish the two already identified simulation gaps.** Implement selectable sequential versus Brownian-bridge Sobol coordinate construction for all QMC path payoffs, and configurable LSMC basis family/degree with robust regression diagnostics.
9. **Add independent reference datasets.** Synthetic identities are excellent but can share implementation errors. Add published benchmark tables or frozen independently generated fixtures with source, units, conventions, and tolerances.

### P1 - reduce architectural and browser risk

10. **Move calibration and SLV work into a dedicated worker.** The current volatility page runs both on the main thread. Add cancellation, progress, elapsed time, and protection against stale calibration results.
11. **Separate development and deployment caching.** The web payload is about 47 MiB, dominated by Python and .NET runtimes, while `serve.py` sends `Cache-Control: no-store` for every asset. Keep that behavior for development, but use content-hashed immutable caching for a hosted build so returning clients do not repeatedly pay the large startup cost.
12. **Generate the polyglot ABI from one schema.** `polyglot-contract.js` currently packs a 64-value header plus schedule into numeric offsets that must be duplicated across languages. Add an ABI version and generate constants, validation, and documentation for all five implementations from one source definition.
13. **Split the numerical monoliths by responsibility.** `exotic-pricer.js`, `volatility-models.js`, and `advanced-pricer.js` are large, high-coupling files. Separate probability/math, payoffs, processes, MC/QMC, PDE, calibration, diagnostics, and serialization into testable modules without changing the public API.
14. **Make portfolio execution dependency-aware.** Pricing is off the UI thread but deals are processed sequentially in one worker. Use a bounded worker pool, reuse identical market/model artifacts, and aggregate scenarios/Greeks without duplicating calibration.

### P2 - production-facing completeness

15. **Add market conventions and event models.** Introduce discount/dividend/forward curves, day-count conventions, holiday calendars, corporate actions, settlement rules, and explicit fixing/event timelines.
16. **Add import/export and audit views.** Users should be able to save and reload deals, portfolios, surfaces, seeds, solver settings, cash-flow traces, and test reports in a stable format.
17. **Automate accessibility and responsive testing.** The current pages load cleanly and use labels/landmarks, but add keyboard-only flows, automated accessibility checks, narrow/mobile viewport screenshots, and chart/table fallbacks.
18. **Harden any hosted deployment.** The loopback server is appropriately small. A public host should add CSP, COOP/COEP where needed, integrity/version controls, HTTPS, dependency vulnerability scanning, and a clear statement that pricing inputs remain local.

## Suggested three-iteration roadmap

### Iteration 1 - engineering foundation

- Establish Git baseline, license, package scripts, and CI.
- Add automated browser smoke/conformance tests.
- Define and version the deal, result, ABI, and calibrated-surface schemas.

### Iteration 2 - calibration-to-pricing pipeline

- Move calibration/SLV to a cancellable worker.
- Persist a fully auditable calibrated-surface artifact.
- Inject that artifact into the path, payoff, and portfolio engines.
- Add noisy-market and convergence fixtures around the existing dense local-vol round trip.

### Iteration 3 - risk and deployment

- Add Greeks, scenarios, cash-flow/event inspection, and portfolio aggregation.
- Complete Brownian-bridge QMC and configurable LSMC.
- Add production asset caching, security headers, accessibility, and responsive CI.

## Recommended acceptance bar

A feature should be called production-ready only when it has a specified contract and conventions, deterministic unit/reduction tests, an independent benchmark, numerical convergence evidence, cross-language scope stated exactly, browser end-to-end coverage, and audit metadata sufficient to reproduce the result.
